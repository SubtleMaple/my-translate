### Bug 1：生词本排序闪回

- **现象**：切排序方式后，底部菜单换页再回来，排序闪回原方式
- **根因**：`vocabStore.setSortBy` 只调 `setSettings` 持久化到主进程，未同步 `settingsStore` 本地状态；重进生词本页 `load()` 读到旧值覆盖

### Bug 2：仅 TUN 模式能联网，普通系统代理无效

- **现象**：Clash TUN 模式可用；普通代理模式（系统代理 127.0.0.1:7897）下 LLM 请求全部失败
- **根因**：主进程 LLM 调用用的是 Node undici fetch（**不跟随系统代理**）；P5 曾误判为 Chromium 网络栈，当时实际靠 TUN 透明代理兜底
- **修复**：`client.ts` 引入可注入 `httpFetch`（默认 globalThis.fetch 保测试）；`index.ts` 启动时 `setFetchImpl(net.fetch)` 切到 Chromium 网络栈——自动跟随系统代理（普通代理模式可用）、无代理直连（TUN 模式不受影响）
- **验证**：真实网络验证见 Bug 3（DeepSeek 直连需走系统代理，通过即证）

### Bug 3：Anthropic 规则连不上第三方网关

- **现象**：cc-switch 里 DeepSeek `/anthropic` 网关可用的配置，应用里连不上
- **根因 1（认证）**：cc-switch 配置用 `ANTHROPIC_AUTH_TOKEN`（Claude Code 发 `Authorization: Bearer`），应用只发 `x-api-key`，DeepSeek 网关不认

## R1 追加：思考模式开关（2026-08-03，分支 feat/thinking-mode-off）

### 背景

deepseek-v4-flash 是思考型模型（默认先输出 thinking 块）。实测思考开启时 `prompt_tokens=85 / completion=17`，关闭后 `prompt_tokens=6 / completion=1`——关闭思考响应更快、费用更低，且详情生成/翻译不再受 thinking 吞预算影响。

### 实测结论（DeepSeek 文档 + curl 验证）

| 格式 | 关闭思考参数 | 实测 |
|---|---|---|
| OpenAI 兼容 | body 加 `"thinking":{"type":"disabled"}`（SDK 中即 extra_body） | ✅ 无 reasoning_content |
| Anthropic | 文档称 `reasoning:{effort:"none"}` | ❌ 实测无效（仍有 thinking） |
| Anthropic | body 加 `"thinking":{"type":"disabled"}` | ✅ 无 thinking 块，input_tokens 85→6 |

**统一采用 `thinking:{type:"disabled"}`**（两种格式均认；官方 Anthropic 的 thinking 参数语义相同，开启时不受影响）。

### 实现

- **`shared/types.ts`**：`LlmProviderConfig` 增加 `thinking: 'auto' | 'off'`（默认 'auto'=不发送任何参数，旧配置经 deepMerge 自动补齐，无需迁移）
- **`llm/client.ts`**：新增 `thinkingBodyParam(config)`（off → `{thinking:{type:"disabled"}}`），openai/anthropic 非流式 body 均附加
- **`llm/translate.ts`**：流式 body 同样附加（两分支）
- **`SettingsView`**：Model 下方新增「思考模式」Select（自动/关闭）+ 说明文案；草稿/切换类型逻辑同步

### 验收结果

| 验收项 | 结果 |
|---|---|
| mock 单测（30 项，新增 I1-I3） | ✅ off→thinking disabled 参数、auto→不发送，openai/anthropic 双格式 |
| 真实 E2E（DeepSeek，思考关闭） | ✅ OpenAI 格式与 Anthropic 格式：testConnection / 流式翻译 / 非流式 全通过 |

## R1 追加：翻译页滚动 + Chip 划线逻辑修复（2026-08-03，分支 fix/translate-ux）

### Bug 1：翻译页整体不能上下滚动，长译文被挤出窗口

- **根因**：TranslateView 根部 `h-full` 锁死高度 = main 高度；内部文本区/按钮/Chip 为固定+自适应高度（不收缩），把结果区 `flex-1` 挤到 0，长译文溢出被裁；外层 main 的 `overflow-y-auto` 因子元素恒等高而永不触发
- **修复**：TranslateView 根部去掉 `h-full`、结果区去掉 `flex-1 overflow-y-auto` → 整页随内容增高，由外层 main 滚动；loading/错误横幅行为不变

### Bug 2：划线不应受词库历史影响

- **旧逻辑**：`existedWords` 来自词库查询（翻译完成 checkWords），历史词划线且**拦截点击** → 无法再选中，count+1 无从谈起
- **新逻辑**：划线 = **本次句子中已加入的词**（确认加入后标记），仅作提示，**不拦截**——划线词照常可点击/拖拽，再次加入走 count+1
- **改动**：
  - `translateStore`：移除翻译完成后的 `checkWords` 词库查询；`existedWords` 语义改为「本次句子已加入」（addToVocab 的 added+existed 归入）；`translate()` 不再清空 existedWords（划线跨重新翻译保留），改输入/清空才复位
  - `WordChips`：划线词点击不再弹 toast 拦截，正常 toggle 选中；样式改为可点（hover 反馈），✓ 角标保留；划线词也可作为拖拽起点
  - 移除整个 checkWords 链路（`RendererApi` / preload / IPC 频道 / vocabRepo.checkWords / ipc handler），死代码清零

1. **单实例锁被残留进程占用的排查**：P2 冒烟启动的 `win-unpacked/My Translate.exe` 未被真正杀死（`Get-Process electron` 按进程名过滤漏掉了它），长期占用单实例锁 → 所有后续 dev/产物运行拿到 `requestSingleInstanceLock: false` 直接 `app.quit()`，表现为「无报错、无 db 文件」。**教训：杀进程必须用 `Get-CimInstance Win32_Process` 按 CommandLine/Name 过滤；冒烟结束要清 `My Translate.exe` 残留。**

5. **AUTOINCREMENT + INSERT OR IGNORE 会消耗序列号**（被忽略的插入也自增）→ id 有空洞，属 SQLite 正常行为，应用无感知，不做处理。
6. 迁移前中文路径打包偶发 ENOENT：首次 `dist:dir` 失败（残留进程锁文件），清进程后重跑成功；P7 若再遇诡异路径错误，先清进程再试（路径问题现已因迁移而规避）。
